# 零成本公网部署可行性验证设计

## 目标

在不续费云服务器、不绑定付费资源的前提下，用一个最小但真实的端到端系统验证正式项目的部署路径。验证对象不是完整产品功能，而是正式项目最容易导致返工的基础设施与跨系统数据链路。

## 已确定的约束

- 总费用为 0；不得依赖已进入回收状态的腾讯云实例。
- 最终服务必须有公网 HTTPS 地址，并能从 GitHub Actions 发起真实请求。
- 应用采用 Python 3.11、FastAPI、Docker，与正式项目保持一致。
- 关系数据进入外部 PostgreSQL；向量数据进入外部 Qdrant，应用容器不依赖本地持久化磁盘。
- 免费平台休眠、冷启动和资源限制必须如实记录，不能把演示环境描述成具有生产 SLA。
- 不在仓库中提交 API Key、数据库连接串或其他密钥。

## 候选方案

### 方案 A：Render + Neon + Qdrant Cloud（采用）

Render 承载单容器 FastAPI 服务，Neon 承载 PostgreSQL，Qdrant Cloud 承载向量检索。三者职责清晰，最接近正式生产中的无状态应用与外部托管数据层。主要风险是 Render 免费实例只有 512 MB 内存且会休眠，必须实际测量冷启动、内存和依赖安装情况。

### 方案 B：Render + Neon pgvector

把关系数据和向量数据都放在 PostgreSQL。资源更少、部署更简单，但不能验证项目明确要求的外部向量数据库，因此只作为 Qdrant 免费服务不可用时的降级方案，不作为首选结论。

### 方案 C：只在本机 Docker Compose 模拟

可验证镜像与服务编排，但无法证明公网平台构建、HTTPS、环境变量、外部网络和 GitHub Actions 回调可用，因此只能作为预检，不能作为上线可行性结论。

## 最小系统边界

验证服务只包含以下能力：

1. `GET /health/live`：仅验证进程存活。
2. `GET /health/ready`：分别检查 PostgreSQL 和 Qdrant，并返回脱敏后的依赖状态。
3. `POST /api/v1/ci-runs`：接收一份限定大小的 pytest JUnit XML 与元数据，使用共享签名密钥鉴权并生成幂等事件 ID。
4. 解析测试失败，将运行记录和结构化失败信息写入 PostgreSQL。
5. 对失败摘要生成确定性的本地测试向量，写入 Qdrant，再执行一次相似失败检索。此处故意不依赖付费模型，以隔离部署验证与模型额度问题。
6. `GET /api/v1/ci-runs/{id}`：读取已持久化结果及相似失败，证明重启后仍可查询。

确定性测试向量只用于验证向量数据库链路，不能冒充最终语义检索质量。正式项目再替换为真实嵌入模型，并用评测集验证召回率。

## 数据流

GitHub Actions 在测试结束后始终上传受限大小的 JUnit 报告；发送脚本计算请求时间戳与 HMAC 签名。FastAPI 校验时间窗口、签名、内容类型和大小后解析报告；数据库事务保存运行与失败记录；随后将失败摘要向量写入 Qdrant，并把检索结果关联到本次运行。重复提交同一仓库、工作流运行 ID 和尝试次数时返回原结果，不重复入库。

## 异常与安全要求

- 缺少或错误签名返回 401；过期时间戳返回 401；重复事件保持幂等。
- XML 使用安全解析方式，禁止外部实体；限制请求体和失败条目数量。
- PostgreSQL 或 Qdrant 不可用时，`ready` 返回非就绪；业务接口返回明确的依赖错误，不伪造成功。
- 日志采用 JSON，包含请求 ID、事件 ID、阶段、耗时和错误类别，不记录密钥或完整数据库地址。
- Docker 进程使用非 root 用户；服务只监听平台提供的端口。

## 验证矩阵

### 本地必须通过

- 单元测试：签名、XML 安全解析、幂等键、大小限制和错误映射。
- 集成测试：真实 PostgreSQL 与 Qdrant 容器的写入、读取和相似检索。
- 镜像测试：以 512 MB 内存限制启动应用并完成完整请求。
- 重启测试：删除并重建应用容器后仍能读取外部数据。

### 公网必须通过

- Render 从仓库 Dockerfile 成功构建并启动。
- 公网 HTTPS 健康检查可访问。
- GitHub Actions 的一份真实失败测试报告能完成签名提交。
- PostgreSQL 和 Qdrant 中都出现对应数据，查询接口返回真实结果。
- 休眠后首次请求的冷启动时间、正常请求延迟和错误日志可观察。
- 重新部署应用后，历史记录仍存在。

## 判定标准

只有本地与公网项目全部通过，才给出“零成本演示部署可行”的结论。以下任一情况发生则判定当前方案失败并立即调整：

- Render 构建或运行持续超过免费资源上限。
- 免费账户要求实际扣费或无法在用户所在地正常创建。
- GitHub Actions 无法安全提交报告。
- 外部 PostgreSQL 或 Qdrant 无法稳定连接，或数据在应用重部署后丢失。
- 公网演示无法通过 HTTPS 访问。

即使全部通过，也只证明“作品演示和工程交付链路可行”，不证明高可用、商业生产 SLA 或中国大陆网络质量。
